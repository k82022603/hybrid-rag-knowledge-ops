# Session Log - 세션 로그 작성

Claude Code 세션의 작업 기록을 저장하여 컨텍스트를 보존하고 작업 연속성을 유지합니다.

## 저장 위치

```
work_logs/session_logs/YYYY-MM-DD_description.md
```

**예시**:
- `2026-01-21_kibana_standup.md` - Kibana 문서화 및 스탠드업 세션
- `2026-01-21_e2e_test.md` - E2E 테스트 세션
- `2026-01-22_sprint02_planning.md` - Sprint 02 계획 세션

> **참고**: 하루에 여러 세션이 있을 경우 description으로 구분

## 파일명 규칙

- **형식**: `YYYY-MM-DD_description.md`
- **description**: 영문 소문자, 언더스코어 구분, 세션 주요 작업 요약
- 공백 대신 언더스코어(`_`) 사용
- 간결하게 (2-4 단어)

## 실행 단계

### 1. 세션 로그 파일 확인/생성

```bash
# 오늘 날짜의 세션 로그 파일 확인
ls work_logs/session_logs/$(date +%Y-%m-%d)_*.md 2>/dev/null

# 없으면 새 파일 생성
```

### 2. 작업 내용 수집

- git log로 커밋 내역 확인
- 수정된 파일 목록 확인
- 대화 내용에서 주요 작업 추출

### 3. 세션 로그 작성

- 템플릿에 맞춰 내용 채우기
- 완료된 작업, 결정사항, 변경 파일 기록
- 다음 작업 및 리스크 정리

## 사용 시나리오

### 세션 시작 시
```
/daily:session-log start
```
- 새 세션 로그 파일 생성
- 이전 세션 로그 참조하여 컨텍스트 복원

### 세션 종료 시
```
/daily:session-log end
```
- 세션 로그 마무리
- 종료 시간, 세션 통계 기록

### 업데이트 모드
```
/daily:session-log update
```
- 진행 중인 세션 로그에 작업 내용 추가

## 용도

| 용도 | 설명 |
|------|------|
| **작업 연속성** | 이전 세션에서 수행한 작업 추적 |
| **컨텍스트 복원** | 새 세션 시작 시 참조 |
| **프로젝트 히스토리** | 시간 순서별 작업 기록 |
| **에이전트 협업** | 에이전트 간 작업 인수인계 |

## ⏰ 시간 기록 규칙

시간을 기록할 때는 반드시 `date` 명령어로 실제 시간을 확인합니다:

```bash
date +"%Y-%m-%d %H:%M KST"
```

> **중요**: 시작 시간, 종료 시간, 기록 시간 등 모든 시간 필드에 대해 시스템 시간을 조회하여 정확한 값을 기록합니다.
