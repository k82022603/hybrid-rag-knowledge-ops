## 💡 Inspiration & Insights

### 1. "도구"를 만드는 것이 가장 빠른 지름길

**깨달음**:
처음엔 PowerPoint를 직접 열어서 슬라이드를 만들려고 했다. 하지만 6개 PPT, 각각 10장씩... 손으로는 불가능했다.

```
❌ 직접 작업:
   PPT 열기 → 슬라이드 추가 → 색상 맞추기 → 도형 그리기 → 텍스트 입력
   → 1개당 2시간 × 6개 = 12시간

✅ 도구 먼저:
   Python 스크립트 작성 (2시간)
   → 실행 (각 1분) × 6개 = 6분
   → 총 2시간 10분
```

**통찰**:
- "급할수록 도구를 먼저 만들어라"
- 반복 작업이 3번 이상이면 자동화가 이득
- 도구는 다음에도 재사용할 수 있다

### 2. 테마의 일관성이 브랜드를 만든다

**깨달음**:
Brown Earth 테마를 모든 PPT에 적용하니, 완전히 다른 내용의 문서들이 **같은 프로젝트에서 나온 것처럼** 보였다.

```
테마 구성:
  Primary:   #795548 (Brown)
  Secondary: #A1887F (Light Brown)
  Accent:    #FF9800 (Orange)
  Dark:      #3E2723 (Dark Brown)
```

**영감**:
- 색상 팔레트 하나가 "정체성"을 만든다
- 디자인 시스템은 문서에도 적용된다
- 일관성 있는 자료는 신뢰감을 준다

### 3. 문서는 "덜어내야" 완성된다

**깨달음**:
CLAUDE.md가 592줄에서 153줄로 줄었다. **74%를 삭제**했는데, 오히려 더 명확해졌다.

```
Before:
├── 프로젝트 개요 (상세)
├── 폴더 구조 (상세)
├── 프롬프트 가이드 (4가지 패턴)
├── 보안 가이드 (상세 + 예시)
├── DB 작업 예시 (3개 DB 각각)
├── 테스트 가이드 (상세)
├── 배포 가이드 (상세)        ← README와 중복
├── 로깅 및 모니터링
├── 커밋 가이드
├── 작업 일지 시스템 (상세)    ← README와 중복
├── 협업 규칙
├── 디버깅 팁
├── 참고 자료 (전체 목록)      ← README와 중복
├── 체크리스트
└── 변경 이력 (v1.0~v2.2)

After:
├── 프로젝트 개요 (표 1개)
├── 폴더 구조 + 파일 규칙
├── 프롬프트 가이드 (좋은/나쁜 예시 1개씩)
├── 보안 규칙 (핵심만)
├── 커밋 메시지 형식
├── 코드 품질 체크리스트
├── 작업 일지 (명령어만)
├── 브랜치 전략
└── 참고 문서 (3개 링크)
```

**배운 점**:
- 문서의 가치는 분량이 아니라 **필요한 정보만 담는 것**
- 중복은 혼란을 만든다
- "이 문서의 목적은 무엇인가?"를 먼저 묻자

### 4. 우선순위가 모든 것을 결정한다

**깨달음**:
내일 할 일을 정하는 과정에서 **설계 완료 전에 구현을 시작하면 안 된다**는 걸 깨달았다.

```
처음 생각:
  "Docker 설정부터 하자, 개발 환경이 필요하니까"

다시 생각:
  "잠깐, API 설계가 없으면 뭘 개발하지?"
  "Backend 설계가 없으면 어떤 구조로 짜지?"
  "암호화 설계가 없으면 보안 요구사항을 어떻게 반영하지?"

결론:
  P0: API 설계서 → Backend 설계서 → 암호화 설계
  P1: 개발 환경 구축 (설계 완료 후)
```

**원칙**:
- 설계 없는 구현은 리팩토링의 시작이다
- "무엇을"이 명확해야 "어떻게"가 의미가 있다
- 기초가 튼튼해야 속도가 나온다

## 🔄 Thinking Process

### 프레젠테이션 생성 과정

```
1단계: 요구사항 분석
  "Brown 테마로 설계서 발표 자료 필요"
  → 어떤 내용? → 설계서 핵심만 추출
  → 몇 장? → 10장 이내
  → 도식화? → PPT 도형 기능 활용

2단계: 도구 설계
  "python-pptx로 자동화하자"
  → 테마 팔레트 정의
  → 슬라이드 템플릿 함수 작성
  → 도형 기반 다이어그램 구현

3단계: 실행 & 반복
  → 1번째 PPT 생성 (플랫폼 설계서)
  → 2번째 PPT 생성 (Frontend)
  → 3번째 PPT 생성 (인증/권한)
  → 4번째 PPT 생성 (UI Storyboard)
  → 각각 다른 요구사항, 같은 도구

4단계: 최적화
  → 듀얼 패널 레이아웃 추가 (와이어프레임 + 설명)
  → 개발자 주의사항 포함
  → 6개 PPT × 평균 10장 = 58장 완성
```
