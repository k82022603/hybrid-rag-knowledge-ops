## 💡 Key Decisions

### 1. 개발 에이전트 vs 런타임 LLM 구분
   - **의사결정**: DeepSeek을 개발 에이전트에서 제외
   - **근거**: DeepSeek은 코드를 생성하는 개발 도구가 아닌, AI Service 내부에서 호출되는 런타임 API
   - **효과**: 역할 혼동 해소, 문서 일관성 확보

### 2. 구현 계획서 형식 표준화
   - **의사결정**: 코드 중심 → Phase/Task/의존성 중심
   - **근거**:
     - 코드 예시는 설계서에서 제공
     - 구현 계획서는 "어떻게"보다 "무엇을 언제" 중심
   - **효과**: 문서 역할 분리, 중복 제거

### 3. 설계서에 서비스 분리 아키텍처 명시
   - **의사결정**: 섹션 3.2 신규 추가
   - **근거**: SpringBoot와 AI Service 분리가 설계서에 명확히 표현되지 않음
   - **효과**: 개발팀이 아키텍처를 명확히 이해 가능

## 📚 Learnings

### 1. 문서 역할 구분의 중요성
   - **설계서**: "무엇을 만들 것인가" (What) - 아키텍처, 코드 예시
   - **구현 계획서**: "어떻게 구현할 것인가" (How) - Phase, Task, 의존성
   - 역할 혼동 시 문서 중복 및 일관성 문제 발생

### 2. 개념 명확화의 가치
   - 작은 개념 혼동(개발 에이전트 vs 런타임 LLM)이 여러 문서에 파급
   - 초기에 명확히 정의하는 것이 중요

### 3. 문서 간 참조 관계 관리
   - 설계서 ↔ 구현 계획서 ↔ 백엔드 계획서 간 일관성 필수
   - 한 문서 수정 시 관련 문서 동시 확인 필요
