## 1. 개요

Claude Code는 **Shift+Tab** 키로 전환 가능한 3가지 인터랙션 모드를 제공합니다.
각 모드는 Claude가 파일을 수정하거나 명령을 실행할 때의 **권한 승인 방식**이 다릅니다.

```
Shift+Tab 순환:

  Default Mode → Auto-Accept Edit Mode → Plan Mode → Default Mode (반복)
```

---

## 2. 모드별 상세

### 2.1 Default Mode (기본 모드)

| 항목 | 내용 |
|------|------|
| **상태 표시** | 표시 없음 (기본 상태) |
| **파일 수정** | 매번 승인 필요 |
| **Bash 명령** | 매번 승인 필요 (allowlist 제외) |
| **파일 읽기** | 자동 허용 |

**동작**: Claude가 파일을 수정하거나 명령을 실행하기 전에 매번 사용자에게 허가를 요청합니다.

```
예시:
  Claude: "Edit file src/app/main.py?"
  사용자: [Y/n] ← 매번 확인
```

**적합한 상황**:
- 새로운 코드베이스를 처음 작업할 때
- Claude의 변경 사항을 하나하나 검토하고 싶을 때
- 민감한 코드 (보안, DB 스키마 등)를 수정할 때

---

### 2.2 Auto-Accept Edit Mode (자동 승인 모드)

| 항목 | 내용 |
|------|------|
| **상태 표시** | `⏵⏵ accept edits on` (하단 표시) |
| **파일 수정** | **자동 승인** (확인 없이 즉시 적용) |
| **Bash 명령** | 여전히 승인 필요 (allowlist 제외) |
| **파일 읽기** | 자동 허용 |

**동작**: Claude가 파일 수정(Edit, Write)을 승인 없이 자동 적용합니다. 단, Bash 명령은 여전히 허가를 요청합니다.

```
예시:
  Claude: [파일 수정 → 즉시 적용, 확인 없음]
  Claude: "Run bash: git commit -m '...'?"
  사용자: [Y/n] ← Bash는 여전히 확인
```

**적합한 상황**:
- 문서 작성/수정 (마크다운 파일 등)
- 다수의 파일을 일괄 수정하는 리팩토링
- Claude의 코드 변경을 신뢰하고 빠르게 진행하고 싶을 때
- 반복적인 파일 수정 작업 (여러 파일에 동일 패턴 적용 등)

---

### 2.3 Plan Mode (계획 모드)

| 항목 | 내용 |
|------|------|
| **상태 표시** | `⏸ plan mode on` (하단 표시) |
| **파일 수정** | **차단** (읽기 전용) |
| **Bash 명령** | **차단** (읽기 전용) |
| **파일 읽기** | 자동 허용 |

**동작**: Claude가 코드를 분석하고 계획만 수립합니다. 파일 수정이나 명령 실행이 차단되어 **안전하게 탐색**할 수 있습니다.

```
예시:
  사용자: "인증 시스템 리팩토링해줘"
  Claude: [코드 분석 → 계획 수립 → 실행 계획서 작성]
  Claude: "계획을 승인하시겠습니까?"
  사용자: [승인 시 → 구현 모드로 전환]
```

**적합한 상황**:
- 복잡한 기능 구현 전 아키텍처 설계
- 여러 파일에 걸친 대규모 변경 전 영향 분석
- 코드베이스 탐색 및 이해
- 구현 전에 방향을 먼저 합의하고 싶을 때

## 3. 모드 비교 요약

| 비교 항목 | Default | Auto-Accept | Plan |
|----------|---------|-------------|------|
| 파일 수정 | 승인 필요 | **자동** | 차단 |
| Bash 실행 | 승인 필요 | 승인 필요 | 차단 |
| 파일 읽기 | 자동 | 자동 | 자동 |
| 속도 | 느림 | **빠름** | - |
| 안전성 | 높음 | 중간 | **최고** |
| 주 용도 | 신중한 작업 | 빠른 구현 | 분석/계획 |

## 4. 작업 유형별 권장 모드

### 4.1 일상 개발 작업

| 작업 | 권장 모드 | 이유 |
|------|----------|------|
| 문서 작성/수정 | **Auto-Accept** | 파일 수정이 많고, 위험도 낮음 |
| 버그 수정 (단일 파일) | **Default** | 변경 사항 검토 필요 |
| 다수 파일 리팩토링 | **Plan → Auto-Accept** | 계획 후 일괄 적용 |
| 새 기능 구현 | **Plan → Default** | 계획 후 단계별 검토 |
| 코드 탐색/분석 | **Plan** | 수정 없이 안전하게 분석 |

### 4.2 CI/CD 및 인프라 작업

| 작업 | 권장 모드 | 이유 |
|------|----------|------|
| 워크플로우 파일 수정 | **Default** | YAML 오류가 CI/CD 전체에 영향 |
| Docker 설정 변경 | **Default** | 인프라 변경은 신중하게 |
| 장애 분석 | **Plan** | 원인 파악 먼저, 수정은 나중에 |
| 장애보고서 작성 | **Auto-Accept** | 문서 작업이므로 빠르게 |

### 4.3 커밋/푸시 작업

| 작업 | 권장 모드 | 이유 |
|------|----------|------|
| git commit/push | **Default** | Bash 명령은 어떤 모드든 승인 필요 |

> **참고**: Auto-Accept 모드에서도 Bash 명령(git commit, push 등)은 항상 승인을 요청합니다. allowlist에 등록된 명령은 예외입니다.

## 5. 본 프로젝트 권장 워크플로우

### 5.1 현재 프로젝트 특성

| 항목 | 상태 |
|------|------|
| 개발 인원 | 1인 + Claude Code |
| 주요 작업 | 설계/구현/문서/CI/CD |
| allowlist | 다수의 Bash 명령 사전 허용 (settings.local.json) |

> ⚠️ **현행화 메모**: 2026-02-08 이후 Agent Teams v2.0 도입으로 "1인 + Claude Code" 방식에서 "1인 + Claude Lead + Agent Teammates(최대 13명)" 방식으로 전환됨. 인터랙션 모드 자체는 동일하게 적용되며, Agent Teams 환경에서는 각 팀원(Teammate)이 독립 세션으로 실행되므로 팀원별로 모드를 독립적으로 설정해야 함.

### 5.2 상황별 권장 모드 전환

```
┌─────────────────────────────────────────────────────────────────┐
│  일반적인 작업 흐름                                               │
│                                                                   │
│  1. 복잡한 작업 시작 → Plan Mode (Shift+Tab x2)                  │
│     "인증 시스템 구현해줘" → Claude가 계획 수립                    │
│                                                                   │
│  2. 계획 승인 후 → Auto-Accept Mode (Shift+Tab x1)               │
│     계획대로 파일 수정이 빠르게 진행                               │
│                                                                   │
│  3. 민감한 변경 필요 시 → Default Mode (Shift+Tab)                │
│     CI/CD 워크플로우, Docker 설정 등                              │
│                                                                   │
│  4. 커밋/푸시 → 어떤 모드든 동일 (Bash 승인 필요)                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 실용적 팁

**가장 많이 쓰게 될 모드**: **Auto-Accept Edit Mode**

이유:
- 1인 개발이라 모든 변경 사항을 직접 확인할 필요성이 낮음
- 문서 작성, 코드 구현 모두 빠르게 진행 가능
- Bash 명령은 여전히 승인이 필요하므로 git push 등의 안전장치는 유지
- allowlist에 이미 다수의 명령이 등록되어 있어 추가적인 편의성 확보

**Plan Mode를 쓸 때**:
- "~~ 구현해줘" 같은 대규모 작업 요청 전
- 코드베이스 분석이나 장애 원인 파악 시
- 여러 접근 방법 중 하나를 선택해야 할 때

**Default Mode를 쓸 때**:
- `.github/workflows/*.yml` 수정 시 (CI/CD 영향)
- `docker-compose.yml` 수정 시 (인프라 영향)
- 보안 관련 코드 변경 시

## 6. CLI 옵션

### 6.1 특정 모드로 시작

```bash
# Plan Mode로 시작
claude --permission-mode plan

# Plan Mode + 단발성 질의
claude --permission-mode plan -p "인증 시스템 아키텍처 분석해줘"
```

### 6.2 세션 중 전환

```
Shift+Tab    모드 순환 (Default → Auto-Accept → Plan → Default)
```
