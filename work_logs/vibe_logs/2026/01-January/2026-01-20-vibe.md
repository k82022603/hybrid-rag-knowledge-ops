## Inspiration & Insights

### 1. Docker 네트워크의 internal: true 교훈
컨테이너 간 격리를 위해 `internal: true`를 설정했지만, 개발 환경에서는 localhost 접근이 필요하다는 것을 깨달음.
**교훈**: 보안과 개발 편의성의 균형을 환경별로 다르게 가져가야 한다.

### 2. 가상 팀의 협업 파워
9개의 Agent가 각자의 전문성을 발휘하며 협업하는 모습이 인상적. PM이 조율하고, 각 전문 Agent가 실행하는 구조가 효과적.

### 3. 테스트가 보여주는 현실
E2E 테스트 0% → 34.7% → 40%의 여정. 테스트는 거짓말하지 않는다. 문제를 발견하고 해결할 때마다 수치가 올라가는 것이 가시적.

### 4. 표준화의 힘 ⭐ NEW
`send_slack.sh` 스크립트 하나로 9개 Agent의 메시지 형식이 통일됨.
- 구분자 자동 추가
- 줄바꿈 문제 해결 (`\n` 리터럴 → 실제 newline)
- 코드 중복 제거 (각 Agent 파일에서 curl 명령 삭제)

**교훈**: "Write once, use everywhere" - 작은 표준화가 큰 일관성을 만든다.

### 5. 개발자 유머의 공감력 ⭐ NEW
"200 OK를 받았지만 마음은 404 Not Found" - 슬픈 사랑이야기 테마로 인사말을 보내니, 개발 용어가 감정과 연결되어 더 와닿음.
- JOIN했지만 CASCADE DELETE
- cosine similarity가 0인 관계
- deprecated된 감정

**인사이트**: 기술 용어도 스토리텔링에 사용하면 팀 문화가 된다.
