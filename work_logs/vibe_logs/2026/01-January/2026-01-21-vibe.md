---

### 3. 에이전트 협업 패턴

오늘 E2E 테스트 100% 달성을 위해 여러 에이전트가 동시에 작업:

```
Infra Agent  → Dockerfile 5개 생성
Data Agent   → pgcrypto 설치
Backend Agent → Keycloak realm 설정
QA Agent     → Phased Testing 구조 도입
```

**발견한 패턴**:
- 각 에이전트는 자신의 전문 영역에 집중
- 병렬 실행으로 시간 절약
- 결과물을 통합하는 것은 orchestrator의 역할

---

### 4. Observability의 "관찰" 철학

Kibana를 추가하면서 생각한 점:

- Prometheus: 메트릭 수집 (숫자)
- Grafana: 대시보드 (시각화)
- Kibana: 로그 탐색 (텍스트)
- Jaeger: 분산 추적 (흐름)

> "각 도구는 시스템의 다른 측면을 '관찰'한다.
> 완전한 Observability는 이들의 조합이다."

## Design Philosophy

### "Convention over Configuration"

오늘 만든 시스템들의 공통 철학:

```
파일명 규칙 정의 → 자동 생성 가능
폴더 구조 정의 → 찾기 쉬움
템플릿 제공 → 일관성 유지
```

> "규칙이 명확하면 의사결정이 줄어든다."
