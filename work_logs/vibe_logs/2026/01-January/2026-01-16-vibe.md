### 1. "누락된 것을 찾는 기술" - Gleaning

**발견**:
Microsoft GraphRAG 논문에서 발견한 Gleaning 기법. LLM에게 "혹시 놓친 엔티티 있어?"라고 물어보는 단순한 아이디어.

```
기존 방식:
  문서 → LLM → 엔티티 추출 → 끝
  (누락된 것들은 그냥 사라짐)

Gleaning:
  문서 → LLM → 엔티티 추출
               ↓
        "놓친 거 있어?"
               ↓
          추가 추출 → 완성
```

**통찰**:
- 한 번 더 물어보는 것이 33% 품질 향상을 만든다
- "다시 확인해봐"는 단순하지만 강력한 전략
- 비용 60% 증가로 품질 33% 향상 = 가성비 있는 투자

### 2. 때로는 "덜어내는 것"이 발전이다

**결정**:
```
Before (Kubernetes):
  ┌─────────────────────────────────────────┐
  │  Master Nodes (3대)                      │
  │  Worker Nodes (5대)                      │
  │  Storage Nodes (2대)                     │
  │  DB Nodes (3대)                          │
  │  ─────────────────────                   │
  │  총 13대 서버                             │
  │  예상 비용: ~$100,000                     │
  │  운영 복잡도: ★★★★★                      │
  └─────────────────────────────────────────┘

After (Docker Compose):
  ┌─────────────────────────────────────────┐
  │  Single Docker Host (1~2대)              │
  │  ─────────────────────                   │
  │  총 1~2대 서버                            │
  │  예상 비용: ~$14,000                      │
  │  운영 복잡도: ★★☆☆☆                      │
  └─────────────────────────────────────────┘

비용 절감: 86%
복잡도 절감: 60%
```

**깨달음**:
- "확장성을 위해" K8s를 선택하려 했다
- 하지만 아직 확장할 것이 없다
- **YAGNI**: You Ain't Gonna Need It
- 필요할 때 확장하면 된다 (Docker Compose → Swarm → K8s)

### 4. 비용과 효과의 트레이드오프

**Gleaning 분석**:
```
횟수별 효과:

  0회: Entity Recall 60%    비용 $0.005    (기준)
  1회: Entity Recall 80%    비용 $0.008    (+33% 품질, +60% 비용)
  2회: Entity Recall 85%    비용 $0.011    (+42% 품질, +120% 비용)
  3회: Entity Recall 87%    비용 $0.014    (+45% 품질, +180% 비용)

  → 1회가 최적!
  → 2회부터는 비용 대비 효과 급감
```

**통찰**:
- 완벽을 추구하면 비용이 기하급수적으로 증가
- 80% 완성이 100% 완성보다 가성비가 좋다
- "충분히 좋은" 것이 최선인 경우가 많다
