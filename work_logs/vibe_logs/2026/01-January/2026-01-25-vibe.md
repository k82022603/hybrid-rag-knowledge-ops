### 2. E2E 테스트의 힘

Playwright로 E2E 테스트 10개를 작성하고 나니, API 경로 불일치 같은 문제가 바로 드러났다.

```
Frontend: /api/v1/auth/login
Backend:  /api/auth/login
→ 404 Not Found
```

단위 테스트만으로는 이런 통합 문제를 잡기 어렵다. E2E 테스트가 "진짜 동작하는지"를 검증한다.

### 3. Gateway + Redis = 네트워크 의존성

Gateway가 Rate Limiter로 Redis를 사용하는데, docker-compose에서 네트워크 연결을 놓쳤다. 단순한 설정 실수지만, 디버깅하는 데 시간이 걸렸다.

**교훈**: 마이크로서비스에서 네트워크 의존성은 항상 명시적으로 관리해야 한다.

## 🧠 Thought Process

### 문제: E2E 테스트 6/10 실패

**1차 분석**: "API가 응답을 안 한다"
- curl로 직접 호출 → 401 Unauthorized
- 로그 확인 → AuthController 접근 전에 Security에서 차단

**2차 분석**: "SecurityConfig 문제인가?"
- `/api/auth/**`는 permitAll
- 하지만 Frontend는 `/api/v1/auth/**`로 호출
- 경로 불일치!

**해결**: AuthController의 `@RequestMapping`을 `/api/v1/auth`로 변경

**3차 분석**: "Gateway에서 또 막힌다"
- Backend 직접 연결(8081) → 10/10 통과
- Gateway 경유(8080) → 6/10 실패
- Gateway 로그 → Redis 연결 실패

**해결**: docker-compose.yml에 `database` 네트워크 추가

**회고**: 문제가 여러 레이어에 걸쳐 있었다. 한 번에 다 고치려 하지 말고, 레이어별로 격리해서 테스트하는 게 중요하다.
