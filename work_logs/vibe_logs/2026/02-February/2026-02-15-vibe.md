## Inspiration & Insights

### 1. "자동화는 신뢰의 문제"

야간점검을 Agent Teams 대신 bash 스크립트로 대체한 것은 기술적 판단이 아니라 신뢰의 문제였다. 사용자가 "Agent Teams 소집"이라고 말한 건, 단순 모니터링이 아니라 각 에이전트의 관점에서 점검하길 원한 것. 스크립트가 더 효율적이라 해도, 사용자의 의도를 먼저 확인했어야 했다.

### 2. Neo4j 배치 삭제의 교훈

34,747개 노드를 한 번에 삭제하려다 Neo4j가 Connection Lost. 이후 1,000건 배치로 나누니 35회 안정적으로 완료. "한 방에 끝내려는 유혹 vs 안전한 배치 처리" - 모든 대량 작업에 적용되는 원칙.

```
단일 삭제 시도 → Connection Lost → Neo4j 재시작 필요
배치 삭제 (1000/회) → 35회 × 0.5초 = 18초, 안정적 완료
```

### 3. merge threshold 100의 효과와 한계

Chunker v3에서 소형 청크 병합 임계값을 20→100으로 올린 결과:
- **효과**: .md 청크 33% 감소, 평균 토큰 77% 증가
- **한계**: 여전히 62.5%가 <100 tokens

한계의 원인은 코드 블록(`\`\`\``)이 3-8 토큰 독립 청크가 되는 구조적 문제. 이건 시맨틱 청커의 분할 단위 자체를 바꿔야 해결 가능하다. merge는 "사후 치료"이지 "예방"이 아니다.

### 4. 밤새 혼자 달린 ETL

v4가 19:46~07:52까지 12시간 동안 1,437개 문서를 묵묵히 처리. OOM 0건, 실패 0건. 어제의 v1 OOM Kill과 비교하면 격세지감. 결국 올바른 설정(10GB 제한 + OCR ON + TableFormerMode.FAST)이 답이었다.

## Ideas

1. **시맨틱 청커 MD 전용 모드**: 코드블록 닫기(`\`\`\``), 짧은 헤더, 구분선(`---`)을 독립 청크로 만들지 않고 이전/이후 청크에 포함시키는 전용 로직. merge보다 근본적 해결.

2. **야간 Agent Teams 자동 소집 시스템**: nohup + Claude API 호출로 정기 Agent Teams 소집. 단순 bash 모니터링이 아닌 에이전트 관점 분석을 자동화.
