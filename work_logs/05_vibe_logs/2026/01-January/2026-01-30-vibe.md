### 1. WSL2 환경의 함정

> "같은 폴더, 다른 OS, 다른 바이너리"

Windows에서 `pip install`하면 Windows wheel, WSL2에서 하면 Linux wheel.
당연한 건데, 혼합 환경에서 작업하다 보면 쉽게 잊는다.

**교훈**: 환경 일관성이 중요하다. WSL2에서만 pip 실행하거나, Docker 쓰거나.

### 3. 테스트가 알려주는 것

RRF 테스트 실패 원인: `_rrf_fusion`이 `SearchResult.score`를 직접 수정함.
같은 객체를 두 번 호출하면 첫 번째 결과가 오염됨.

```python
# Bad: 같은 리스트 재사용
results = [make_search_result(...) for i in range(5)]
fused_k1 = rrf_fusion([results], k=1)
fused_k1000 = rrf_fusion([results], k=1000)  # results가 이미 수정됨!

# Good: 각 호출에 새 리스트
results_k1 = [make_search_result(...) for i in range(5)]
results_k1000 = [make_search_result(...) for i in range(5)]
```

**교훈**: 함수가 입력을 수정하는지 주의. Immutable 패턴이 안전함.

## Creative Thoughts

### max_tokens 고민

처음엔 `max_tokens=1024`가 작다고 생각했는데,
실제 프로덕션 설정은 `4096`이었고, RAG 용도로 충분하다.

Claude API 권장:
- 일반 분석: 1,024 ~ 4,096
- 코드 생성: 2,000 ~ 8,000
- Agent 워크플로우: 8,192 ~ 16,384

RAG 답변은 보통 500~2,000 토큰이니 4,096이면 여유.
**"충분한 것과 과한 것의 차이"** - 비용 최적화 관점.
