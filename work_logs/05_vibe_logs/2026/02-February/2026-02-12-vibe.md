## Inspiration & Insights

### "측정하지 않으면 추측일 뿐이다"
오늘의 하이라이트. SemanticChunker의 max_chunk_size=2048 설정을 보고 ETL이 "10-20% 절단 가능성"을 이론적으로 추정했다. 하지만 RAG이 ES에서 실측한 결과는 2%뿐. chunk_size=600이라는 설정이 실제로는 대부분의 청크를 600자 내외로 잘 나누고 있었다. 코드를 읽는 것과 데이터를 보는 것은 다르다.

### 메모리의 진실 — 4GB vs 10GB
ai-service 컨테이너의 메모리를 4GB로 알고 있었는데, Infra가 docker inspect로 확인하니 실제 limit은 10GB였다. 4GB는 reservation(보장)이지 limit(상한)이 아니었다. 이 하나의 발견이 text_len=2048 전환의 안전성을 보장해줬다. 가정을 검증하는 것의 중요성.

### Claude Code API 비용이 진짜 비용
GPU 클라우드 비교하다가 깨달은 점 — CPU 임베딩은 $0이지만, 임베딩 관련 분석/튜닝/모니터링에 쓰는 Claude Code API 비용이 GPU $1-2보다 훨씬 크다. 도구 비용보다 엔지니어링 시간이 비싸다는 보편적 진리의 AI 버전.

## Ideas & Experiments

### 전문가 합의 패턴의 효과
오늘만 3번(Phase 2 재처리, 속도 튜닝, text_len 분석) 전문가 3인 토의를 진행했다. 같은 문제를 ETL/RAG/Infra 각각의 관점에서 보면 놓치는 게 없다. 특히 RAG이 "실측 해보자"고 해서 이론 vs 실측 차이를 발견한 것이 결정적이었다.

### Idempotent 설계의 안심감
임베딩 스크립트가 idempotent하게 설계되어 있어서, 노트북 꺼져도 재시작하면 이어서 진행된다. 이런 설계가 "밤새 돌려놓고 자도 된다"는 안심감을 준다. 배치 처리 시스템에서 idempotency는 선택이 아니라 필수.
