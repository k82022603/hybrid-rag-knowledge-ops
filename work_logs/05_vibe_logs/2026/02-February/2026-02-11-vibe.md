## Inspiration & Insights

### "가장 좋은 디버깅은 체계적인 디버깅이다"

하루 동안 6개의 버그를 연속으로 수정. 각 버그가 서로 다른 레이어에 걸쳐 있었음:
- **Gateway 레이어**: 405 Method Not Allowed
- **DB 레이어**: Lucene 특수문자, Neo4j Fulltext 인덱스
- **인증 레이어**: Keycloak JWT issuer URI
- **Backend 레이어**: 503 Timeout, Stats 엔드포인트 미구현
- **Frontend 레이어**: API 불일치, UX 모순

풀스택 디버깅이 가능한 이유: 각 레이어의 로그를 읽을 수 있고, 에러 메시지를 추적할 수 있기 때문.

### Lucene 특수문자 교훈

`CI/CD`라는 평범한 용어가 Neo4j Fulltext 쿼리에서 500 에러를 유발.
- `/`가 Lucene 쿼리 파서에서 정규식 구분자로 해석됨
- 사용자 입력을 DB 쿼리에 넣기 전 항상 이스케이프 필요
- **보안과 안정성은 같은 뿌리**: SQL injection 방어와 동일한 원칙

### 3-Phase ETL 전략의 탄생

2-worker 임베딩 포함 ETL → ETA 66시간 → 비현실적
즉시 전략 변경: "파싱/저장 먼저, 임베딩 나중에"
- Phase 1 (텍스트): 13.6분에 739파일
- Phase 2 (바이너리): 2워커로 진행중
- Phase 3 (임베딩): BGE-M3 CPU 배치

**핵심 인사이트**: CPU-bound 작업(임베딩)과 I/O-bound 작업(파싱)을 분리하면 전체 처리 시간을 크게 단축.
