## 완료된 작업

### 1. Neo4j Graph Search 3단계 매칭 전략 구현

**파일**: `knowledge_service/src/app/services/search.py` (`_graph_search()`)

#### 문제
- 기존 `e.name CONTAINS word` 방식은 쿼리 단어가 엔티티 이름의 부분문자열인 경우에만 매칭
- 대부분의 검색 쿼리에서 엔티티를 찾지 못해 항상 0건 반환

#### 해결: 3단계 접근
| Step | 전략 | 설명 |
|------|------|------|
| Step 1 | 역방향 CONTAINS | `query CONTAINS entity_name` - 쿼리 안에 엔티티 이름이 포함되는 경우 |
| Step 2 | 정방향 CONTAINS | `entity_name CONTAINS word` - 엔티티 이름 안에 쿼리 단어가 포함되는 경우 |
| Step 3 | Content 폴백 | Step 1+2 결과 0건이면 Chunk content에서 키워드 검색 |

#### 검증 결과
| 쿼리 | 매칭 Step | 결과 건수 |
|------|-----------|-----------|
| "Neo4j 그래프 데이터베이스" | Step 1+2 | 4건 |
| "LLM 중심 기술" | Step 3 (폴백) | 5건 |
| "RAG LangGraph" | Step 1+2 | 5건 |

### 2. RRF Fusion 후 Primary Source 결정 로직 추가

**파일**: `knowledge_service/src/app/services/search.py` (`_rrf_fusion()`)

#### 문제
- RRF 융합 후 `result.source`가 항상 첫 번째 소스(vector)로 고정
- 같은 chunk가 여러 소스에서 발견되면 첫 번째 소스의 source 값만 유지되는 버그

#### 해결
- `source_ranks`에서 가장 높은 순위(낮은 rank 숫자)를 가진 소스를 primary source로 결정
- `result.source = min(ranks, key=ranks.get)` 추가
- Source Type 배지가 각 결과의 실제 주요 기여 소스를 정확히 표시

### 3. Graph Source의 graph_context 전달

**파일**: `knowledge_service/src/app/services/rag_pipeline.py`, `knowledge_service/src/app/agents/rag_workflow.py`
