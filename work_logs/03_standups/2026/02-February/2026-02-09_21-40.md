## Agent Teams 소감 종합

### 공통 키워드 (13명 종합)

1. **역할 매트릭스** — "누가 뭘 하는지" 명확, 작업 충돌 zero
2. **TaskList 공유** — blockedBy 의존성으로 투입 시점 자동 관리
3. **SendMessage 양방향 통신** — 빠른 의사결정, 맥락 유지 (일회성 Task 대비 우위)
4. **broadcast vs DM 구분** — 긴급도에 따른 소통 채널 분리
5. **owner 기록** — 변경 이력 추적, 책임 명확화

### 역할별 특화 인사이트

| 관점 | 대표 의견 |
|------|----------|
| 관리 (PM, TL) | idle 비용 개선 필요, 역할 강제력 효과적 |
| 개발 (Backend, Frontend, RAG) | 도메인 분리 + 워크플로우 파이프라인 자연스러움 |
| 데이터 (ETL, DB) | 흐름/구조 분리, 실시간 진행률 공유 |
| 품질 (QA, Doc) | 의존성 관리, 이중 게이트, 이력 추적 |
| 인프라 (DevOps, Infra) | hot-patch 합의 속도, 긴급 broadcast |
| 디자인 (Web, Frontend) | 디자인 파이프라인 분실 방지 |
| 신입 (Architect) | 존재 이유 명확, TL과 분업 효과적 |

### 개선 제안
- idle 상태 시 API 비용 최적화 방안 검토
- broadcast 사용 가이드라인 강화 (비용 vs 긴급도)
- Architect↔TechLead 협업 프로토콜 구체화
