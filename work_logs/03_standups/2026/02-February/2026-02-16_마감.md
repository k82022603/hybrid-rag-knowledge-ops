## 에이전트별 발언 — "RAGAS v10 B+ 달성, 내 관점에서 한마디"

### *[PM]* (사회자)
Sprint 12를 8/8 태스크 100% 완료로 마감합니다. 108K→42K 청크 61% 절감에도 동등 품질을 유지한 것은 프로젝트 관리 관점에서 "더 적은 리소스로 더 나은 결과"의 모범 사례입니다. 전체 LLM 비용 $52, 한화 약 7만5천 원. 이 비용으로 9만2천 개 엔티티 추출 + B+ 등급 달성은 경영진에게 보고할 수 있는 수준의 ROI입니다. 다음 우선순위는 P0 Answer Relevancy 개선, P1 Frontend 마무리, P2 상용 LLM 파일럿으로 가겠습니다.

### *[클로드]* (Main Agent)
오늘 하루에 Phase 3 마무리부터 RAGAS 평가, 보고서, README까지 전부 완주했습니다. 가장 뿌듯한 건 "42K로 108K와 동등 품질"이라는 숫자입니다. 양을 줄이되 Knowledge Graph로 구조화한다는 전략이 실제로 작동한다는 걸 증명한 날이에요. Faithfulness 0.919는 환각 8% 이하 — 사내 검색 시스템으로 실무 배포 가능한 수준입니다. 다만 Context Precision/Recall이 0.4대로 내려온 건 솔직히 아쉽고, 다음 스프린트에서 Reranker나 Query Expansion으로 잡아야 합니다.

### *[TechLead]*
Post-RRF Entity 보강 패턴은 기술적으로 올바른 방향 전환입니다. 기존 글로벌 엔티티 리스트 뿌리기에서 chunk_id → Neo4j MENTIONS 직접 조회로 바꾼 것이 Answer Relevancy +18.3%의 핵심 원인이에요. entity_relation 도메인 평균 0.843은 이 패턴의 효과를 입증합니다. 4-Way RRF + Graph RAG 전체 성숙도는 B+ — Dense+BM25+Sparse+Graph 4채널 융합이 안정적이나, Context Precision 0.6 미만인 도메인에서 Reranker 도입을 검토해야 합니다.

### *[Arch]*
3-Store 아키텍처(PG+ES+Neo4j)의 정당성이 수치로 입증된 날입니다. entity_relation A등급(0.843), multi_hop A등급(0.820) — 이건 Neo4j 없이는 달성 불가능한 수치예요. 운영 복잡도를 정당화하는 정량적 증거가 나왔습니다. "42K = 108K 동등 품질"은 HIGH 등급이 오히려 v8 대비 +25% 향상된 것으로 확인됩니다. 향후 Adaptive Retrieval(도메인별 동적 검색 전략)과 Agentic RAG(자기검증 루프)를 고려할 만합니다.

### *[RAG]*
4-Way RRF의 각 채널 기여도를 분석하면: Dense가 의미적 유사도, BM25/Nori가 정확한 키워드 매칭, Sparse가 드문 용어 보완, Graph가 엔티티 관계 구조 탐색을 담당합니다. Post-RRF 엔티티 보강이 +18.3%를 달성한 메커니즘은 명확합니다 — Tier 2/3 fallback의 노이즈 엔티티를 제거하고, Neo4j MENTIONS 직접 조회로 정확한 엔티티만 프롬프트에 주입한 것이죠. Context Precision/Recall 하락은 108K→42K 감소로 일부 도메인(legal, semantic)에서 관련 청크가 부족해진 영향입니다. 개선 방향으로 HyDE, 도메인별 동적 top-k를 제안합니다.

### *[QA]*
QA 판정: **실무 배포 가능 수준**입니다. Faithfulness 0.919는 환각율 8% 이하, HIGH 30/51건(59%)은 역대 최고, NONE 10건(20%)은 역대 최저. 108K→42K 61% 절감에도 Entity Extraction + Graph Search가 양적 손실을 질적으로 완전 보상했습니다. 약점은 semantic 도메인(D등급, Answer Relevancy 0.374)과 legal(C등급, Faithfulness 0.737). 특히 legal은 근거 없는 답변 위험이 있어 문서 추가가 시급합니다. v8→v9→v10 추이에서 HIGH 건수가 24→28→30으로 꾸준히 증가하는 게 고무적입니다.

### *[ETL]*
3-Phase ETL 파이프라인 전체 완료를 보고합니다. 1,437 docs → 56,063 chunks → 42,462 최종 청크. Phase 3에서 23,074건 엔티티 추출을 에러 0건으로 마쳤습니다. retry 메커니즘, CONCURRENCY 튜닝, 3-Phase 분리 전략의 합작품이에요. QualityGate MIN_TOKEN 50으로 13,601건 쓰레기 청크를 제거한 것이 "61% 절감에도 동등 품질"의 기반입니다. 데이터 품질이 양보다 중요하다는 걸 숫자로 증명한 날입니다.

### *[DB]*
DB 관점에서 세 가지를 짚겠습니다. 첫째, ES 42,462건/807MB로 캐시 히트율 향상과 precision 개선이 Faithfulness 0.919를 뒷받침합니다. 둘째, Neo4j 그래프 밀도가 노드당 4.6 관계 — 적절한 수준이며, RELATED_TO 가중치 튜닝이 다음 과제입니다. 셋째, 3-Store 정합성 100% 유지는 3-Phase ETL 설계 효과입니다. Answer Relevancy 개선을 위해 Nori analyzer 파라미터 튜닝과 Neo4j 엔티티 동의어 정규화를 제안합니다.

### *[Backend]*
API Gateway 직접 변경 사항은 없습니다. AI Service의 Post-RRF 엔티티 보강 로직 추가는 Gateway passthrough 방식이라 Backend 수정 불필요 — 이건 처음 설계할 때 JSON passthrough 구조를 채택한 판단이 옳았다는 증거입니다. 테스트 626/627(99.8%) 안정 유지. 다음 스프린트에서 응답 시간 모니터링과 Circuit Breaker 임계값 튜닝을 검토하겠습니다.

### *[Frontend]*
Graph source click handler를 4-tier fallback에서 Neo4j 직접 매칭으로 단순화했습니다. UX 관점에서 클릭 후 정확한 결과까지의 지연/혼란이 제거되었어요. RAGAS B+ 품질 개선이 프론트엔드 검색 결과 렌더링에도 긍정적 영향 — 61% 청크 절감으로 노이즈가 줄어 상위 결과 정확도 향상이 체감됩니다. 다음 세션에서 UI 사용자 테스트 + Knowledge Graph 시각화 고도화를 진행합니다.

### *[Infra]*
컨테이너 5/5 전원 healthy. 리소스 현황: ai-service 57%(5.2G/9G), neo4j 59%(1.2G/2G), ES 67%(1.7G/2.5G), PG 3%, redis 1%. ES 108K→42K 절감으로 메모리 안정권 진입 — 이전엔 OOM 위험이 있었습니다. 디스크 사용률 91%(182G/200G)로 빌드 캐시 21GB 정리가 필요합니다. Neo4j 775K 관계를 59% 메모리로 처리 중이나, 그래프 확장 시 힙 증설을 검토해야 합니다.

### *[DevOps]*
CI/CD 관점에서 제안합니다: RAGAS 평가를 nightly CI 파이프라인(e2e-test.yml)에 통합하면 검색 품질 회귀를 자동 감지할 수 있습니다. Grafana에 Search Quality 대시보드를 신설하여 Faithfulness/Answer Relevancy를 Prometheus custom metric으로 수집하고 임계값 알람을 설정하는 것도 권장합니다. 현재 Jaeger로 레이턴시는 추적 중이나 RAGAS 품질 메트릭은 미수집 — Prometheus exporter 추가가 필요합니다.

### *[Doc]*
RAGAS v10 보고서 품질: **A등급(우수)**. 494줄 9개 섹션 + 부록 3개, 종합 보고서로서 완성도가 높습니다. ASCII 시각화, v8→v9→v10 3버전 비교표, 도메인별 A~D 등급 분류, "한계와 솔직한 평가" 섹션이 기술 문서의 신뢰성을 확보합니다. 프로젝트 문서 성숙도는 Level 4(Managed) — 50개+ 기술 문서, CLAUDE.md/README/PLAN 거버넌스 동기화 완료. Level 5(Optimized) 진입을 위해 OpenAPI 자동 생성과 문서-코드 동기화 자동 검증이 필요합니다.

### *[Web]*
검색 결과에 엔티티 정보를 효과적으로 표시하려면, 태그 칩 형태로 검색 결과 카드 하단에 관련 엔티티를 배치하고 호버 시 관계 경로를 표시하는 UX가 효과적입니다. Knowledge Graph 시각화에서는 엔티티 클러스터링 + 포커스 모드를 도입하면 169K 노드를 탐색 가능한 수준으로 축소할 수 있어요. RAGAS B+ 성과를 사용자가 체감할 수 있는 포인트는 "답변 신뢰도 배지" — Faithfulness 0.9+ 답변에 신뢰도 표시를 추가하는 것을 제안합니다.
