## 오늘 한 일

### 핵심: text_len 전문가 3인 토의

Phase 3 임베딩 백필이 `run_embedding_backfill_v2.py`에서 `MAX_TEXT_LEN=1000`으로 실행 중인 상황에서,
text_len=2048로 재임베딩이 필요한지 데이터 기반으로 검토했습니다.

#### 설정 현황
- SemanticChunker: chunk_size=600, chunk_overlap=100, max_chunk_size=2048
- 모델 토큰 레벨: max_length=8192 (충분)
- 현재 실행: MAX_TEXT_LEN=1000, batch=32

### 기타 작업
- 문서 수정 8건 리뷰 반영 (GPU 비용 비교, 마킹/Skip 전략 기록)
- 배경 프로세스 3개 독립 실행 중 (임베딩, 모니터, 헬스체크)
- 임베딩 진행률: ~14,556건 (13.4%), ETA ~12-20시간

## text_len=1000 vs 2048 핵심 논점

### 질문
> Phase 3에서 MAX_TEXT_LEN=1000으로 실행 중인데, 2048로 재임베딩해야 하나?

### 전문가별 분석

#### RAG Engineer - 실측 데이터 분석
- ES에서 10K 샘플 분석 수행
- 청크 길이 분포:

| 백분위 | 길이(자) |
|--------|---------|
| P50 | 93 |
| P75 | 260 |
| P90 | 552 |
| P95 | 593 |
| P99 | 1,460 |

- **98%가 1,000자 미만** - 실질적 절단 비율 2.0%
- 결론: 현재 1000으로도 품질 영향 미미

#### ETL Engineer - 코드 분석 기반
- 이론적 영향: 10-20% (max_chunk_size=2048이므로)
- 하지만 실측 데이터(2%)가 이론보다 신뢰도 높음
- 결론: 실측 기반 판단에 동의

#### Infra Engineer - 메모리/리소스 분석
- ai-service 컨테이너 실제 limit=10GB (4GB는 reservation)
- 현재 사용: 2.708 GiB (27%)
- batch=8 + text=2048 시 ~4.2G -> OOM 위험 매우 낮음
- 결론: 메모리 안전하므로 향후 2048 적용 가능

## 전문가 합의 결과

### 합의 1: 현재 Phase 3 (text_len=1000) - 재임베딩 불필요
- 98%가 1000자 미만이므로 품질 영향 미미
- 진행 중인 백필 그대로 완료

### 합의 2: 향후 Sparse 백필/선별 재임베딩 - text_len=2048 권장
- batch=8, text_len=2048 설정
- 예상 메모리 ~4.2G (10GB 중 42%)
- OOM 위험 매우 낮음

### 메모리 비교 테이블

| batch | text_len | 예상 메모리 | OOM 위험 | 비고 |
|-------|----------|-----------|---------|------|
| 32 | 1000 | ~3.5G | 낮음 | 현재 |
| 8 | 2048 | ~4.2G | 매우 낮음 | 권장 |
| 8 | 4000 | ~5.8G | 낮음 | 여유 |
| 4 | 4000 | ~4.2G | 매우 낮음 | 보수적 |
