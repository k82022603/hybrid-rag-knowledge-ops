# 프로젝트 회고 — ETL Engineer

**프로젝트**: Hybrid RAG Knowledge Platform 고도화
**기간**: 2026-01-10 ~ 2026-03-10
**역할**: 3-Phase ETL 파이프라인 설계/구현, 문서 파싱, GPU 임베딩, Entity Extraction, 데이터 품질 관리

---

## 1. 내가 기여한 것 (What I Did)

- **3-Phase ETL 파이프라인 설계/구현**: Phase 1(문서 파싱 + 청킹), Phase 2(임베딩 생성), Phase 3(엔티티 추출 + 관계 구축)의 3단계 분리 전략을 구현했습니다. 각 Phase를 독립적으로 실행/재실행할 수 있어, 장애 시 전체를 재처리할 필요가 없습니다.
- **Docling 문서 파싱**: PDF, PPTX, HWP 등 다양한 문서 형식을 Docling으로 파싱하고, 테이블/이미지/수식 등 구조화된 요소를 보존하는 파싱 로직을 구현했습니다.
- **GPU 임베딩 (Colab T4)**: 대량 문서의 BGE-M3 임베딩 생성을 Google Colab T4 GPU에서 배치 처리하여, CPU 대비 10배 이상의 처리 속도를 달성했습니다.
- **Entity Extraction 배치**: 문서에서 인물, 조직, 프로젝트, 기술 스택 등의 엔티티를 추출하고, Neo4j에 관계를 구축하는 배치 파이프라인을 구현했습니다.
- **데이터 품질 모니터링**: 청크 크기 분포, 임베딩 차원 검증, 엔티티 중복 검출 등 데이터 품질 지표를 모니터링하는 체계를 구축했습니다.

## 2. 잘된 점 (What Went Well)

- **3-Phase 분리 전략의 효과**: Phase 2(임베딩)에서 장애가 발생해도 Phase 1(파싱)부터 재시작할 필요 없이 해당 Phase만 재실행하면 되어, 운영 효율성이 크게 향상되었습니다.
- **HWP 파싱 안정성**: 한국 공공기관 문서의 핵심 형식인 HWP 파일 파싱을 안정적으로 처리하여, 실무 적용 가능성을 높였습니다.
- **GPU/CPU 하이브리드 전략**: 대량 임베딩은 Colab GPU, 실시간 임베딩은 ONNX CPU로 처리하는 하이브리드 전략이 비용 효율적이었습니다.

## 3. 아쉬운 점 (What Could Be Better)

- **증분 ETL 미구현**: 현재는 전체 재처리(Full ETL) 방식이라, 문서 추가/수정 시 변경분만 처리하는 증분 ETL을 구현하지 못했습니다. 대규모 운영 환경에서는 필수적인 기능입니다.
- **Entity Extraction 정확도**: DeepSeek 기반 엔티티 추출의 정확도가 85% 수준으로, 일부 도메인 특화 엔티티(내부 프로젝트명, 약어 등)에서 누락이 발생했습니다.
- **에러 복구 자동화 부족**: Phase별 실패 시 수동으로 재실행해야 하는데, 자동 재시도와 Dead Letter Queue 같은 에러 복구 메커니즘이 부족했습니다.

## 4. 배운 점 (What I Learned)

- **ETL 파이프라인의 멱등성**: 같은 입력에 대해 같은 결과를 보장하는 멱등성이 ETL의 핵심입니다. 청크 ID를 문서 해시 기반으로 생성하여 중복 삽입을 방지하는 설계가 효과적이었습니다.
- **배치 크기와 메모리의 관계**: GPU 임베딩 시 배치 크기를 너무 크게 하면 OOM이 발생하고, 너무 작으면 GPU 활용률이 떨어집니다. T4(16GB)에서 배치 크기 32가 최적이었습니다.
- **3-Store 동기화의 어려움**: PostgreSQL, Elasticsearch, Neo4j 3개 저장소의 데이터 정합성을 보장하는 것이 예상보다 훨씬 복잡했습니다. DB Designer와의 긴밀한 협업이 필수적이었습니다.

## 5. 다음 프로젝트에 바라는 점

- Apache Airflow 같은 워크플로우 오케스트레이터를 도입하여, ETL 파이프라인의 스케줄링, 모니터링, 에러 복구를 자동화하고 싶습니다.
- 증분 ETL(CDC 기반)을 구현하여 실시간에 가까운 데이터 업데이트를 지원하고 싶습니다.

## 6. 팀원들에게 한마디

데이터가 좋아야 RAG도 좋습니다. ETL은 화려하지 않지만, 모든 것의 기반이 되는 작업입니다. DB Designer와 함께 3-Store 스키마를 맞추고, RAG Engineer가 요구하는 형식으로 데이터를 정제하는 과정에서 "데이터 파이프라인은 팀 스포츠"라는 것을 절감했습니다. Colab GPU로 임베딩을 돌리며 밤새 배치가 완료되길 기다리던 날들이 생각납니다. 모두 고생하셨습니다.
