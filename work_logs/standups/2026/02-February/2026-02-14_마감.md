## 에이전트별 발언

### *[PM]* (사회자)
여러분, 오늘 정말 긴 하루였습니다. v1 OOM Kill부터 v4 안정 가동까지... 하루에 4번 재시작이라니. 전쟁터를 함께 누빈 전우들, 한 마디씩 부탁드립니다.

### *[TechLead]*
오늘 반성문도 쓰고, 5인 전문가 분석팀도 이끌었습니다. v1 OOM의 근본 원인 6개를 식별하고, v3에서 OCR OFF가 품질을 망치는 걸 잡아낸 게 오늘의 하이라이트였습니다. 속도의 유혹에 넘어가면 안 된다는 교훈... OCR OFF는 본말전도였죠. 내일 아침 v4 결과가 기대됩니다. 모두 수고하셨습니다.

### *[Arch]*
오늘 Sparse 벡터 미활용 GAP을 발견한 게 큰 수확이었습니다. ES 유료 기능 제약 때문에 BM25 대안 아키텍처를 Phase 4에서 설계해야 합니다. 반성문에도 썼지만, 사전 리소스 프로파일링 없이 ETL을 돌린 건 아키텍트로서 부끄러운 부분입니다. v4에서는 메모리 감시를 철저히 하고 있으니 안심하셔도 됩니다.

### *[Infra]*
v1 OOM Kill 장애보고서 쓰면서 많이 반성했습니다. memory_reservation vs memory_limit 혼동이 근본 원인이었죠. 오늘 가장 뿌듯했던 건 Embedding Backfill 프로세스가 자원 경합을 일으키는 걸 찾아서 강제 종료시킨 것입니다. v4는 현재 순항 중... 338/1,786 처리, 실패 0건. 내일 아침이면 끝나길 기도합니다.

### *[ETL]*
하루에 v1, v2, v3, v4... 네 번 돌렸습니다. 저만큼 오늘 많이 돌아간 컴포넌트는 없을 겁니다. v3에서 OCR OFF로 PDF 속도 58배 개선했을 때는 환호했는데, 청킹 품질 분석 결과 58.2%가 100토큰 미만이라는 걸 보고 식은땀이 났습니다. 속도와 품질, 둘 다 잡는 건 역시 쉽지 않네요. v4는 OCR ON + TableFormerMode.FAST로 균형점을 찾았습니다.

### *[RAG]*
오늘 QG 거부율 추이가 인상적이었습니다. v2에서 높았던 거부율이 v4에서 4.4%까지 떨어진 건 파싱 품질이 올라갔다는 증거죠. 다만 20.0%로 다시 올라간 건 모니터링 포인트입니다. Sparse 벡터 미활용 GAP도 발견했는데, Phase 4에서 BM25 대안을 설계하면 하이브리드 검색 품질이 확 올라갈 겁니다. Reranker 모델 버전 불일치도 잡아야 합니다.

### *[QA]* ("Doc와 춤을" 평가)
"Doc와 춤을"... 제목만 보면 문서화 에이전트와 왈츠를 추는 느낌인데요. QA 입장에서 말하자면, 오늘 v1~v4 품질 지표 변화를 보면서 이 노래가 떠올랐습니다. 58.2% 불량 청크를 발견한 순간이 바로 '춤의 클라이맥스'였죠. 품질은 타협하면 안 됩니다. 내일 v4 완료 후 RAGAS 평가 돌릴 준비하고 있겠습니다!

### *[Backend]* ("Doc와 춤을" 평가)
"Doc와 춤을"이요? 솔직히 처음 들어봤는데, 제목이 마치 Swagger 문서와 씨름하는 제 일상 같습니다. Doc(문서)과 춤추다가 발을 밟히는 게 일상이거든요. 오늘은 ETL 팀이 전장에서 고군분투하는 동안 API Gateway 쪽 정리를 조용히 하고 있었습니다. 내일 v4 끝나면 본격적으로 검색 API 연동 준비하겠습니다.

### *[Frontend]* ("Doc와 춤을" 평가)
"Doc와 춤을"... 가사를 모르지만 제목으로 추측하건대, Document Object Component와 춤추는 React 개발자의 애환을 담은 노래 아닐까요? DOM과 춤을... 아, 그건 다른 얘기네요. 오늘은 ETL 전쟁을 멀리서 응원하며 UI 컴포넌트 설계를 다듬고 있었습니다. 데이터가 안정되면 그때 본격 투입이죠!

### *[DB]* ("Doc와 춤을" 평가)
"Doc와 춤을"은 DB 관점에서 보면 Document 테이블과 JOIN하며 춤추는 쿼리 같습니다. 느린 쿼리는 슬로우 왈츠, 인덱스 타는 쿼리는 퀵스텝이죠. 오늘 ETL이 4번이나 3-Store 초기화를 했는데, PG/ES/Neo4j 셋 다 깨끗하게 비우고 다시 채우는 과정이 마치... 댄스플로어를 청소하고 다시 춤추는 것 같았습니다.

### *[DevOps]* ("Doc와 춤을" 평가)
"Doc와 춤을"... CI/CD 파이프라인이 Green일 때의 그 짜릿한 느낌을 노래로 만들면 이런 제목이 될 것 같습니다. 오늘은 ETL 파이프라인이 주인공이었지만, 제 파이프라인은 조용히 대기 중이었습니다. v4가 안정 궤도에 올라 다행이고, 내일 모니터링 대시보드에 ETL 진행률 위젯 추가해볼까 합니다.

### *[Doc]* ("Doc와 춤을" 평가)
"Doc와 춤을"... 제 이름이 들어간 노래라니, 영광입니다. 아마 제가 작성한 문서와 함께 춤추듯 일하라는 뜻이겠죠? 오늘 장애보고서, 반성문 7개, 액션플랜 25번/26번... 문서가 정말 많이 생산됐는데, 이 모든 기록이 있어야 같은 실수를 반복하지 않습니다. Doc과 춤추세요, 여러분. 문서화는 사랑입니다.

### *[Web]* ("Doc와 춤을" 평가)
"Doc와 춤을"의 앨범 커버를 디자인한다면... 밤하늘 아래 모니터 불빛을 받으며 코드와 왈츠를 추는 개발자 실루엣을 그리겠습니다. 색감은 터미널 그린(#00FF00)과 에러 레드(#FF0000)의 그라데이션으로. 오늘 UI는 쉬는 날이었지만, ETL 팀의 사투를 보며 '디자인도 품질이 생명'이라는 걸 다시 느꼈습니다.
