## 부주제: Sonnet 4.6 vs Opus 4.6 — 에이전트 모델 티어링 회고

### 배정 현황

| 티어 | 모델 | 에이전트 수 | 역할 |
|------|------|:---------:|------|
| Tier 1 | Opus 4.6 | 2개 | TechLead, Software Architect |
| Tier 2 | Sonnet 4.6 | 11개 | PM, Backend, Frontend, RAG, ETL, DB, Infra, DevOps, QA, Doc, Web |

### 오늘 실전 결과 (08_deliverables 현행화)

| 에이전트 | 모델 | 작업 | 소요시간 | 품질 |
|---------|------|------|:-------:|:----:|
| PM | Sonnet 4.6 | 01_project_final_report | ~2분 | 양호 |
| Backend | Sonnet 4.6 | 05_api_specification (8개 라우트 전수 대조) | ~6분 | 우수 |
| Frontend | Sonnet 4.6 | 04_user_manual | ~4분 | 양호 |
| DB | Sonnet 4.6 | 06_database_design | ~4분 | 양호 |
| QA | Sonnet 4.6 | 08_test_report + 09_known_issues | ~15분 | 우수 |
| DevOps | Sonnet 4.6 | 03_operator_manual + 07_installation_guide | ~11분 | 우수 |

### 비용 비교

| 항목 | Opus 4.6 | Sonnet 4.6 | 절감율 |
|------|:--------:|:----------:|:-----:|
| Input | $15/M tokens | $3/M tokens | 80% |
| Output | $75/M tokens | $15/M tokens | 80% |
| 11개 에이전트 전환 효과 | - | - | ~73% |

### 핵심 발견

1. **Sonnet 4.6은 일상 작업에 충분**: 문서 현행화, 코드 대조, 파일 수정에서 Opus와 큰 품질 차이 없음
2. **Rate limit 안정성**: Sonnet 6개 에이전트 병렬 실행 전원 성공 vs Opus 7개 에이전트 전원 실패 (rate limit)
3. **Opus의 진가**: 아키텍처 의사결정, 복잡한 트레이드오프 분석 (Neo4j 스키마 통일 같은) 에서 차별화
4. **권장 기준**: "판단이 필요하면 Opus, 실행이 필요하면 Sonnet"

### 주의사항

- Rate limit은 모델별 독립 — Opus 집중 사용 시 한도 도달 빠름
- 병렬 에이전트 6개 이상 시 Sonnet이 rate limit 측면에서 안전
- "모든 에이전트에 Opus"는 비용 낭비이자 rate limit 리스크
