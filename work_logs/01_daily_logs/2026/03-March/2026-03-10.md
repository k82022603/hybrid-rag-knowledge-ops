## Key Insights

### Reranker 2-Pass 중복 증명
```
Cross-encoder 입력: (query, content) → score
입력 score 필드는 사용되지 않음 (_sync_rerank → _batch_process → _compute_scores)
동일 모델 + 동일 후보 = 동일 점수
→ 2nd Pass는 1st Pass의 비싼 복제 (레이턴시 +100%, 품질 변화 없음)
```

### REST vs Chat API 차이 원인
```
v16 (REST): rerank_pool = min(top_k*3, 50) = 15개 → Mean 0.763
v17 (Chat): rerank_pool = min(len, top_k*2, 50) = 10개 → Mean 0.723
차이: 후보 풀 크기 (15 vs 10) → HybridRetriever에 top_k*3 통일 권장
```

### Faithfulness 하락은 평가 인프라 한계
```
v16/v17 모두 Faithfulness 하락 (0.859, 0.800 vs v11 0.935)
→ DeepSeek API를 RAGAS judge로 사용 시 시점별 변동성 존재
→ 절대값보다 상대 순위에 집중해야 함
```
