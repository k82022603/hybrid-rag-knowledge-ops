### 2.2 backend_implementation_plan.md

#### 개요

| 항목 | 내용 |
|------|------|
| **문서 목적** | SpringBoot 백엔드 구현 계획 |
| **작업 유형** | 섹션 3.5 수정 |
| **변경 범위** | "3.5 AI Service (Python)" → "3.5 AI Service 연동" |
| **평가** | ⭐⭐⭐⭐⭐ (5/5) |

#### 변경 내역

**수정 사유**:
- 기존: SpringBoot가 AI 모델과 직접 연동하는 것처럼 기술
- 변경: SpringBoot는 AI Service REST API만 호출

**변경 내용**:

| 항목 | 변경 전 | 변경 후 |
|------|--------|--------|
| **섹션명** | 3.5 AI Service (Python) | 3.5 AI Service 연동 |
| **내용** | AI 모델 직접 연동 방식 | REST API 호출 패턴 |
| **구현 방식** | Python 라이브러리 사용 | WebClient 비동기 호출 |

**추가된 내용**:

1. **아키텍처 흐름도**
   ```
   SpringBoot → AI Service → DeepSeek/ES/Neo4j
   ```

2. **역할 분담 테이블**
   - SpringBoot: CRUD, 비즈니스 로직, 트랜잭션
   - AI Service: 검색, 추출, 임베딩, 답변 합성

3. **API 엔드포인트 목록**
   - `/api/v1/search/*`
   - `/api/v1/extract/*`
   - `/api/v1/embed`

4. **WebClient 설정 및 코드 예시**

5. **Circuit Breaker 패턴**
   - Resilience4j 기반 장애 대응

#### 평가

| 평가 항목 | 점수 | 상세 |
|----------|------|------|
| **명확성** | 5/5 | SpringBoot ↔ AI Service 역할 구분 명확 |
| **일관성** | 5/5 | 설계서 섹션 3.2와 일치 |
| **실용성** | 5/5 | 코드 예시로 즉시 구현 가능 |

#### 판정

```

│   ✅ APPROVED - 역할 분리 명확화                          │
│                                                          │

```
AI Agent = Claude Code + DeepSeek + Antigravity (3개)
```

**변경 후 (명확)**:
```
개발 에이전트 = Claude Code + Antigravity (2개)

런타임 LLM = DeepSeek V3.2
  - AI Service 내부에서 API 호출
  - 엔티티 추출, 의도 분석, 답변 합성
