### 3.3 핵심 발견

#### 발견 1: Reranker가 Context Precision/Recall을 대폭 개선

```
v10 (no reranker):  Context Precision 0.489 / Recall 0.474
v11 (+reranker):    Context Precision 0.618 / Recall 0.672
                                      +26.4%         +41.8%
```

**해석**: v10에서 청크 수 감소로 하락했던 Context Precision/Recall이 Reranker 도입으로 v9를 넘어서는 수준으로 회복되었다. Cross-encoder가 RRF 퓨전 후 결과를 정밀하게 재순위하여, 실제로 유용한 컨텍스트가 상위에 배치되었다.

#### 발견 2: HIGH 등급 역대 최고 갱신 (33건, 65%), NONE 역대 최저 (6건, 12%)

```
v8:  HIGH 24건 (47%) — 108K 청크, 엔티티 없음
v9:  HIGH 28건 (55%) — 56K 청크, 엔티티 없음
v10: HIGH 30건 (59%) — 42K 청크, 엔티티 있음
v11: HIGH 33건 (65%) — 42K 청크, 엔티티 + Reranker  ← 역대 최고
```

**NONE도 역대 최저**: 6건 (12%) — v8/v9 11건 → v10 10건 → v11 6건으로 지속 감소.

#### 발견 3: Answer Relevancy 소폭 하락은 Reranker 특성

```
v10: Answer Relevancy 0.647
v11: Answer Relevancy 0.621 (-0.026)
```

**원인**: Reranker가 컨텍스트 순서를 재배치하면서 답변 생성의 초점이 다소 이동. 그러나 Faithfulness가 0.919→0.935로 오히려 개선되었으므로, 답변의 정확성은 높아지고 있다. Answer Relevancy 하락은 "질문에 대한 직접적 답변" vs "정확한 답변" 사이의 미세한 트레이드오프이다.

#### 발견 4: Faithfulness 0.935 — 환각 6.5% 이하

```
v8:  0.919 (환각 8.1%)
v10: 0.919 (환각 8.1%)
v11: 0.935 (환각 6.5%)  ← 역대 최고
```

**해석**: Reranker가 관련성 높은 컨텍스트를 상위에 배치함으로써, LLM이 근거 없는 추측을 하는 빈도가 줄어들었다. 실무 배포 기준인 "환각 10% 이하"를 충분히 충족한다.

## 5. Entity Extraction 효과 분석

### 5.1 Entity Extraction이 검색에 미친 영향

v10에서 Graph Search는 각 결과에 대해 **청크별 Neo4j 엔티티를 직접 조회**한다.
이전(v9)에서는 글로벌 엔티티 리스트를 사용하거나 제목에서 추출한 미검증 엔티티를 사용했다.

```
v9 방식 (미검증):
  Query → Graph Search → 글로벌 Entity 리스트 반환
  → 모든 결과에 동일한 엔티티 할당 (부정확)

v10 방식 (Neo4j 검증):
  Query → 4-Way RRF → Top-K 결과 선정
  → 각 chunk_id로 Neo4j MENTIONS 관계 조회
  → 해당 청크에 실제 연결된 엔티티만 할당 (정확)
```

## 8. 프로젝트 총평

### 8.1 프로젝트가 달성한 것

이 프로젝트는 **"Graph RAG 기반 지능형 지식 검색 시스템"** 이라는 이름 그대로, 전통적인 키워드 검색과 벡터 검색만으로는 도달할 수 없는 수준의 답변 품질을, 지식 그래프와 엔티티 추출을 결합하여 실제로 달성했다.

가장 주목할 점은 **데이터의 양이 아닌 구조화의 질이 검색 성능을 결정한다** 는 것을 수치로 입증한 것이다. v8 시스템은 108,000개의 청크를 무차별적으로 인덱싱하여 검색 커버리지를 확보하는 전략을 취했다. v10 시스템은 그 중 61%를 의도적으로 제거하고 42,462개의 청크만 남겼음에도 불구하고, 동등하거나 그 이상의 검색 품질을 달성했다. 이것은 단순히 "불필요한 데이터를 제거했다"는 소극적 의미가 아니다. 92,209개의 엔티티 노드와 775,366개의 관계를 Neo4j 그래프로 구축함으로써, 비정형 텍스트 덩어리에 불과했던 문서 청크들이 서로 의미적 연결을 갖춘 지식 네트워크로 전환된 것이다.

이 전환의 효과는 도메인별 성적에서 명확하게 드러난다. 엔티티 간 관계를 묻는 entity_relation 도메인에서 7건 전부 HIGH 등급을 달성했다는 것은, 시스템이 "Neo4j와 Elasticsearch의 역할 차이"나 "Spring Cloud Gateway와 FastAPI의 역할 분담" 같은 비교/관계형 질문에 대해 단순 키워드 매칭이 아닌, 실제 엔티티 간 연결 관계를 기반으로 답변을 생성할 수 있게 되었음을 의미한다. 여러 청크를 연결하는 추론이 필요한 multi_hop 도메인에서도 7건 중 6건이 HIGH를 기록했다. 이는 Knowledge Graph가 단일 문서의 한계를 넘어 여러 문서에 걸친 정보를 연결하는 "추론 경로"를 제공하고 있음을 보여준다.

### 8.2 기술적 의의

이 프로젝트의 기술적 의의는 크게 네 가지로 정리할 수 있다.

**첫째, 4-Way RRF + Reranker 파이프라인의 실효성을 검증했다.** Dense Vector, Sparse Vector, Keyword (Nori BM25), Graph Search의 4가지 검색 채널을 RRF(Reciprocal Rank Fusion)로 결합하고, BGE-Reranker로 정밀 재순위하는 구조를, 실제 한국어 문서 1,437건(42,462 청크)을 대상으로 7개 도메인 51개 질문에 걸쳐 체계적으로 평가한 사례는 드물다. 특히 한국어에 특화된 Nori 분석기를 적용한 BM25 검색과 BGE-M3 다국어 임베딩을 결합하여 한국어 문서에서의 Hybrid 검색 최적 구성을 확인한 것은 실무적 가치가 있다.

**둘째, 3-Phase ETL 파이프라인이라는 실용적 아키텍처를 확립했다.** Phase 1(문서 파싱+청킹), Phase 2(GPU 임베딩), Phase 3(엔티티 추출)을 분리함으로써, GPU 리소스가 제한된 환경(WSL2, CPU 전용)에서도 Google Colab의 무료 GPU를 활용한 임베딩 처리가 가능해졌다. 이는 소규모 팀이나 개인 프로젝트에서 대규모 RAG 시스템을 구축할 때 현실적으로 적용 가능한 접근법이다. 39,259건의 엔티티 추출을 3-워커 병렬(CONCURRENCY=8)로 처리하면서도 에러 0건을 달성한 것은 파이프라인의 안정성을 입증한다.

**셋째, Post-RRF 엔티티 보강이라는 새로운 패턴을 적용했다.** 기존 Graph RAG 시스템에서는 검색 단계에서 그래프를 활용하는 것이 일반적이지만, v10에서는 RRF 퓨전 이후 최종 결과의 chunk_id로 Neo4j MENTIONS 관계를 직접 조회하여 각 청크에 실제 연결된 엔티티만 할당하는 방식을 채택했다. 이는 "검색은 4-Way로 다양하게 하되, 그래프 정보는 결과 보강에 활용한다"는 전략으로, 검색 재현율을 유지하면서도 답변 관련성을 높이는 효과를 가져왔다.

**넷째, Reranker가 Post-RRF 파이프라인에서 가장 높은 ROI를 제공함을 실증했다.** v11에서 BGE-Reranker-Base(ONNX)를 RRF 퓨전 직후에 적용한 결과, Context Precision +26.4%, Context Recall +41.8%라는 대폭 개선을 달성했다. 이는 v10에서 청크 수 감소로 하락했던 검색 품질 지표가 Reranker 단일 변경으로 v9 수준을 넘어서는 수준으로 회복되었음을 의미한다. 코드 변경량 대비 효과가 가장 큰 개선 항목이었다.

### 8.3 비용 대비 성과

이 프로젝트에서 가장 인상적인 수치 중 하나는 비용이다. 전체 Entity Extraction(Phase 1+2)에 소요된 DeepSeek API 비용은 약 $50(한화 약 72,500원)이다. 동일한 작업을 GPT-4o로 수행했다면 약 $852(약 123만원), Claude Opus로 수행했다면 약 $5,977(약 867만원)이 소요되었을 것이다. 7만 원대의 비용으로 92,209개의 엔티티와 775,366개의 관계를 추출하고, 이를 통해 검색 품질을 B+ 등급까지 끌어올린 것은, DeepSeek V3.2의 가격 경쟁력이 단순히 "저렴하다"를 넘어 **"실용화를 가능하게 한다"** 는 수준임을 보여준다.

RAGAS 평가 자체도 51개 쿼리에 대해 검색+답변 생성+라이브러리 평가까지 총 349초(약 6분)에 $0.27로 완료되었다. 이 정도의 비용이면 매일 정기적으로 품질을 모니터링하는 것도 부담이 없다. 실제로 이 프로젝트에서는 v8, v9, v10 세 차례에 걸쳐 동일한 51개 질문으로 평가를 반복 수행하면서 시스템 변경의 효과를 정량적으로 추적할 수 있었다. 이러한 반복적 품질 측정이 가능했던 것은 평가 비용이 거의 무시할 수 있는 수준이었기 때문이다.

### 8.4 한계와 솔직한 평가

객관적으로 이 시스템에는 분명한 한계가 존재한다.

**Context Precision(0.618)과 Context Recall(0.672)은 양호하지만 완벽하지 않다.** v11에서 Reranker 도입으로 v10 대비 대폭 개선되었으나, 검색된 10개의 컨텍스트 중 약 62%만 실제로 유용하고, 답변에 필요한 정보의 약 67%만 검색되고 있다. 특히 legal 도메인(Context Precision 0.448)과 graph_entity 도메인(0.539)에서 개선 여지가 남아 있다.

**Answer Relevancy(0.621)는 v10(0.647) 대비 소폭 하락했다.** Reranker가 컨텍스트 순서를 재배치하면서 LLM의 답변 생성 초점이 다소 이동한 것이 원인이다. 그러나 Faithfulness가 0.919→0.935로 개선되었으므로, "질문에 직접적인 답변" vs "정확한 답변" 사이의 미세한 트레이드오프로 해석할 수 있다.

**legal 도메인(0.592, C등급)은 여전한 약점이다.** Reranker로 Context Recall이 0.429→0.571로 개선되었으나, 근본 원인인 법률 도메인 문서 부족은 해결되지 않았다. Faithfulness 0.863은 기술 도메인(0.886~1.000) 대비 낮아, 근거 없는 추측성 답변 위험이 존재한다.

**Nori 미적용 사고(32일간 미발견)에서 드러난 검증 프로세스의 취약성은 기술적 부채로 남아 있다.** 이 사고는 코드 리뷰 3건에서 모두 "설계서에 있으니 OK"로 통과시켰다가 실제로는 플러그인이 설치되지 않았던 것으로, "설계서에 적혀 있다고 구현된 것이 아니다"라는 뼈아픈 교훈을 남겼다. 현재 E2E 동작 확인 프로세스를 강화했지만, 자동화된 검증 파이프라인(CI/CD 단계에서 _analyze API 확인 등)은 아직 구축되지 않았다.

### 8.5 프로젝트의 위치

이 프로젝트의 결과를 업계 벤치마크와 비교하면, Faithfulness 0.935는 상용 RAG 시스템의 상위권에 해당한다. 환각(hallucination) 비율이 6.5%라는 것은 사내 지식 검색 시스템으로 실무에 배포 가능한 수준이다. 산술 평균 0.711(A- 등급)은 한국어 도메인 특화 문서를 대상으로 한 점을 감안하면 상당히 높은 수치다.

가장 의미 있는 성과는 **"42K 청크 + Knowledge Graph + Reranker로 108K 청크를 넘어서는 성능"** 을 달성한 것이다. v8(108K 청크)의 산술 평균 0.632 대비 v11(42K 청크)의 0.711은 **+12.5%** 향상이다. 이는 스토리지 61% 절약, 검색 응답 시간 단축(인덱스 크기 감소), 그리고 유지보수 비용 절감과 함께 품질까지 개선한 것이다.

총 투입 비용 약 $52(75,400원)으로 92,209개 엔티티를 추출하고, 3-Phase ETL 파이프라인을 확립하고, 4-Way RRF + Reranker + Graph RAG 검색 시스템을 구축한 것은, 이 프로젝트가 "연구 프로토타입"이 아닌 **"비용 효율적 실용 시스템"** 을 지향했음을 보여준다. A- 등급(산술 평균 0.711)과 HIGH 65%(33/51건)는, 이 비용으로 달성한 성과로서 충분히 의미 있다.

DeepSeek V3.2는 가격만 보면 경량 모델 수준이지만, 실제 추론 능력은 GPT-4o에 근접한다. 이 "가격은 mini, 성능은 full" 포지셔닝이 Entity Extraction 같은 대량 반복 + 고품질 추론 작업에서 압도적 비용 효율을 만들어낸다.

### 9.5 결론

| 판단 기준 | 결론 |
|----------|------|
| **비용 효율 1위** | DeepSeek V3.2 — $52로 B+ 등급 달성 |
| **절대 품질 1위** | Claude Opus 4.6 — 하지만 102배 비용 ($5,314) |
| **동일 예산($50) 내 최선** | DeepSeek V3.2 — 유일하게 풀사이즈 성능 제공 |
| **품질 대비 비용 증분** | GPT-4o($775)는 15배 비용에 품질 +10-15% 예상 — ROI 낮음 |
| **추천** | **DeepSeek V3.2를 메인 LLM으로 유지**, 품질 크리티컬 작업만 GPT-4o 병행 |

이 프로젝트는 DeepSeek V3.2의 비용 효율성이 **"실험적으로 재미있는 수준"이 아니라 "실용 시스템 구축을 가능하게 하는 수준"** 임을 실증했다. 약 7만 원의 LLM 비용으로 92,209개 엔티티 추출, 775,366개 관계 구축, 42,462개 청크 기반 4-Way RRF 검색 시스템을 완성하고, RAGAS B+ 등급의 품질을 달성한 것은 소규모 팀이나 스타트업에서도 Production-grade Graph RAG 시스템을 구축할 수 있다는 가능성을 보여준다.
