## 1. 요약

현재 E2E 테스트 스위트가 181개 테스트를 보유하고 있으나, Backend 로그 분석 결과 **실제 API 통합 테스트가 매우 제한적**임이 확인되었습니다. 대부분의 테스트가 UI 렌더링만 검증하며, 실제 Backend API 호출은 로그인 API(`/api/v1/auth/login`)에만 집중되어 있습니다.

### 핵심 발견사항

| 항목 | 현황 | 문제점 |
|------|------|--------|
| 총 테스트 수 | 181개 | - |
| UI 테스트 | ~85% (약 154개) | Mock 데이터로 렌더링만 검증 |
| API 직접 테스트 | ~15% (약 27개) | api-integration.spec.ts에 집중 |
| Backend 로그 호출 | Login API만 | Dashboard, Search, Bookmarks 미호출 |
| Mock Interceptor | 활성화됨 | 개발 환경에서 auth API 가로채기 |

### 2.2 Mock 데이터 사용 현황

**Mock Interceptor 분석** (`src/services/mockAuthInterceptor.ts`):

```typescript
// 문제 코드 발췌 (main.tsx 라인 13)
installMockAuthInterceptor();  // 무조건 실행됨

// mockAuthInterceptor.ts의 조건 (라인 153-161)
export const shouldUseMockAuth = (): boolean => {
  return (
    import.meta.env.DEV &&
    (import.meta.env.VITE_USE_MOCK_AUTH === 'true' ||
      !import.meta.env.VITE_API_BASE_URL)
  );
};
```

**Mock이 가로채는 API 목록**:

| API 엔드포인트 | Mock 응답 | 실제 Backend 호출 |
|---------------|----------|------------------|
| `/api/v1/auth/login` | Mock 유저 반환 | X (가로챔) |
| `/api/v1/auth/refresh` | Mock 토큰 반환 | X (가로챔) |
| `/api/v1/auth/logout` | 204 반환 | X (가로챔) |
| `/api/v1/auth/me` | Mock 유저 반환 | X (가로챔) |
| 기타 API | Pass-through | O (단, 호출 시도 없음) |

**영향**:
- 개발 환경에서 인증 API가 실제 Backend로 전달되지 않음
- E2E 테스트가 Mock 응답을 실제 응답으로 오인
- 테스트 환경에서 `VITE_USE_MOCK_AUTH` 미설정 시 Mock 사용 가능

## 4. 근본 원인 분석 (Root Cause Analysis)

### 4.1 테스트 전략 부재

| 원인 | 상세 |
|------|------|
| 명확한 가이드라인 없음 | UI 테스트 vs API 테스트 구분 기준 미정의 |
| 테스트 피라미드 미적용 | Unit < Integration < E2E 비율 미설정 |
| 목표 메트릭 부재 | API 커버리지, Response Time 기준 미설정 |

### 4.2 Mock vs Real API 환경 분리 미흡

```
현재 상태:
┌─────────────────────────────────────────────────────────────┐
│  개발 환경                                                   │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ main.tsx                                             │    │
│  │   └─ installMockAuthInterceptor() ← 무조건 실행     │    │
│  │                                                      │    │
│  │ mockAuthInterceptor.ts                              │    │
│  │   └─ shouldUseMockAuth()                            │    │
│  │      └─ DEV && (MOCK_AUTH=true || !API_BASE_URL)    │    │
│  └─────────────────────────────────────────────────────┘    │
│                                                              │
│  테스트 환경 (Playwright)                                    │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ TEST_ENV=docker?                                     │    │
│  │   └─ 불명확 - Mock 사용 여부 판단 어려움            │    │
│  │                                                      │    │
│  │ VITE_USE_MOCK_AUTH=?                                │    │
│  │   └─ 미설정 - 기본값으로 Mock 사용 가능             │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘

권장 상태:
┌─────────────────────────────────────────────────────────────┐
│  개발 환경 (로컬)                                            │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ VITE_USE_MOCK_AUTH=true                             │    │
│  │   → Mock 인증 사용                                  │    │
│  └─────────────────────────────────────────────────────┘    │
│                                                              │
│  테스트 환경 (E2E with Docker)                              │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ VITE_USE_MOCK_AUTH=false                            │    │
│  │ TEST_ENV=docker                                     │    │
│  │ VITE_API_BASE_URL=http://localhost:8081             │    │
│  │   → 실제 Backend 연동                               │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 PM 지시 미이행

PM이 "Mock 사용하지 마세요"라고 지시했으나:

1. **코드 레벨 조치 미흡**: `mockAuthInterceptor` 비활성화 조건 불명확
2. **환경 변수 관리 미흡**: 테스트 환경별 설정 파일 부재
3. **검증 부재**: Mock 사용 여부 확인 로그/알림 없음

## 8. 결론

현재 E2E 테스트는 **양적으로는 충분(181개)**하나, **질적으로 API 통합 검증이 부족**합니다. 특히:

1. **Dashboard, Bookmarks, Profile API**가 전혀 테스트되지 않고 있음
2. **Mock Interceptor**가 테스트 환경에서도 활성화되어 실제 API 검증을 방해
3. **테스트 유형 구분 없이** 모든 테스트가 "E2E"로 분류되어 착시 유발

Sprint 05 품질 완성 목표 달성을 위해 **P0 조치를 1일 이내에 완료**하고, **P1 조치를 Sprint 내에 완료**해야 합니다.
