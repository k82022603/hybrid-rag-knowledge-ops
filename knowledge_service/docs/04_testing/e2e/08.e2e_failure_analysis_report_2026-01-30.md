## 2. 실패 유형별 상세 분석

### 유형 A: UI 컴포넌트 상태 불일치 (14건)

**증상**: 컴포넌트가 예상과 다른 상태로 렌더링

| 테스트 | 예상 | 실제 | 원인 |
|--------|------|------|------|
| Dashboard - Quick Search Enter | 검색 페이지로 이동 | 이동 안됨 | 라우팅 이벤트 미발생 |
| Dashboard - Escape 키 | 입력 클리어 | 클리어 안됨 | 키보드 이벤트 핸들러 미등록 |
| Dashboard - Time Greeting | "Good morning" 등 | 텍스트 없음 | 시간대 로직 또는 SSR 이슈 |
| Dashboard - Mobile Stats Stack | 카드 세로 배치 | 가로 배치 | 반응형 CSS 미적용 |

**근본 원인**:
```typescript
// 문제: 테스트가 Mock API 응답 기대
const statsSection = page.locator('[data-testid="stats-section"]');
// 실제: Docker 환경에서는 실제 API 호출 → 응답 지연 → 타이밍 이슈
```

**개선 방안**:
```typescript
// 해결: 명시적 대기 및 조건부 검증
await page.waitForResponse('**/api/stats', { timeout: 10000 }).catch(() => {});
const statsSection = page.locator('[data-testid="stats-section"]');
await expect(statsSection).toBeVisible({ timeout: 10000 });
```

### 유형 B: 선택자 매칭 실패 (8건)

**증상**: `<option>` 요소 visibility 검증 실패

| 테스트 | 선택자 | 실패 원인 |
|--------|--------|----------|
| search-filters - Document Type Options | `option:has-text("All Types")` | `<option>`은 dropdown 닫혀있으면 hidden |
| search-filters - Apply Filter | `span:has-text("Type: technical")` | 2개 요소 매칭 (strict mode) |
| search-filters - Filter Badge | `[data-testid="filter-badge"]` | data-testid 미정의 |

**근본 원인**:
```typescript
// 문제: <option> 요소는 <select>가 열려있을 때만 visible
await expect(options.filter({ hasText: 'All Types' })).toBeVisible();
// 실제: <select>가 닫혀있으므로 <option>은 DOM에 있지만 hidden
```

**개선 방안**:
```typescript
// 해결 1: 값 검증으로 변경
const select = page.locator('#filter-doc-type');
await expect(select).toHaveValue('');  // 기본값 확인
await expect(select.locator('option')).toHaveCount(5);  // 옵션 개수 확인

// 해결 2: select를 클릭하여 열기
await select.click();
await expect(options.filter({ hasText: 'All Types' })).toBeVisible();
```

      .toBeVisible({ timeout: 30000 });
  });
});

## 6. 결론

### 왜 평균은 높은데 개별은 낮은가?

1. **가중치 불균형**: auth.spec.ts(100%)는 10개, search-filters.spec.ts(44%)는 25개
   - auth 기여: 10/146 = 6.8%
   - search-filters 기여: 25/146 = 17.1%
   - → 낮은 테스트가 전체에 더 큰 영향

2. **시스템적 실패 패턴**: 같은 원인이 여러 테스트에 영향
   - `<option>` visibility → 10개 테스트 실패
   - 탭 전환 로딩 → 5개 테스트 실패
   - → 하나의 수정으로 여러 테스트 동시 개선 가능

3. **테스트 설계 시점 vs 실행 환경**
   - 설계: Mock 환경 기준
   - 실행: Docker 실제 서비스
   - → 환경 차이가 체계적 실패 유발

### 핵심 개선 포인트

| 순위 | 수정 대상 | 예상 영향 | 난이도 |
|:----:|----------|----------|:------:|
| 1 | search-filters 선택자 | +14개 테스트 | 낮음 |
| 2 | 탭 전환 대기 로직 | +5개 테스트 | 중간 |
| 3 | 키보드 이벤트 | +2개 테스트 | 중간 |

**Phase 1만 완료해도**: 79% → **89%** 예상
